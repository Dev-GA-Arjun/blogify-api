## 2. User Schema

File:

```text
src/models/users.models.js
```

The User schema is defined using Mongoose.

```javascript
const userSchema = new mongoose.Schema({
    username: {
        type: String,
        required: true,
        unique: true,
        trim: true
    },
    email: {
        type: String,
        unquie: true,
        trim: true,
        required: true,
        lowercase: true
    },
    password: {
        type: String,
        minLength: 6,
        trim: true,
        required: true
    }
}, {
    timestamps: true
})
```

The model is created using:

```javascript
const User = mongoose.model("User", userSchema);
```

### User Fields

| Field       | Type     | Constraints                                 |
| ----------- | -------- | ------------------------------------------- |
| `_id`       | ObjectId | Automatically generated by MongoDB/Mongoose |
| `username`  | String   | Required, unique, trimmed                   |
| `email`     | String   | Required, trimmed, lowercase                |
| `password`  | String   | Required, minimum length 6                  |
| `createdAt` | Date     | Automatically generated                     |
| `updatedAt` | Date     | Automatically generated                     |

## 3. Post Schema

File:

```text
src/models/posts.models.js
```

The Post schema is:

```javascript
const postsSchema = new mongoose.Schema({
    title: {
        type: String,
        required: true,
        unique: true,
        trim: true
    },
    content: {
        type: String,
        required: true
    },
    author: {
        type: mongoose.Schema.Types.ObjectId,
        ref: User,
        required: true
    }
}, {
    timestamps: true
})
```

The model is created using:

```javascript
const Posts = mongoose.model("Posts", postsSchema)
```

### Post Fields

| Field       | Type     | Constraints               |
| ----------- | -------- | ------------------------- |
| `_id`       | ObjectId | Automatically generated   |
| `title`     | String   | Required, unique, trimmed |
| `content`   | String   | Required                  |
| `author`    | ObjectId | Required, references User |
| `createdAt` | Date     | Automatically generated   |
| `updatedAt` | Date     | Automatically generated   |

## 4. User-Post Relationship

The Post model contains:

```javascript
author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: User,
    required: true
}
```

The `author` field does not store the complete User document.

It stores the user's ObjectId.

Conceptually:

```text
User
----------------
_id
username
email
password
      |
      | referenced by
      v
Post
----------------
_id
title
content
author -> User._id
```

This represents a one-to-many relationship:

```text
One User -> Many Posts
```

## 5. Mongoose Populate

The relationship can be resolved using Mongoose `populate()`.

For retrieving all posts:

```javascript
Posts.find(filter)
    .sort(sortOptions)
    .skip(skipValue)
    .limit(limitValue)
    .populate('author', 'username');
```

For retrieving a single post:

```javascript
Posts.findById(id)
    .populate('author', 'username email');
```

This allows the API to return selected user information without storing duplicated user information inside every Post document.

## 7. Read All Operation

File:

```text
src/services/posts.services.js
```

Implementation:

```javascript
const posts = await Posts.find(filter)
    .sort(sortOptions)
    .skip(skipValue)
    .limit(limitValue)
    .populate('author', 'username');
```

The operation supports:

### Author Filtering

```javascript
if(author){
    filter.author = author;
}
```

### Sorting

```javascript
if(sortBy){
    const [field, order] = sortBy.split(':');
    sortOptions[field] = order === 'desc' ? -1 : 1;
}
```

If no sorting parameter is provided, posts are sorted by:

```javascript
sortOptions.createdAt = -1;
```

### Pagination

```javascript
const skipValue = (pageValue - 1) * limit;
```

Then:

```javascript
.skip(skipValue)
.limit(limitValue)
```

are applied to the MongoDB query.

## 9. Update Operation

File:

```text
src/services/posts.services.js
```

Implementation:

```javascript
const updatePost = async (id, updatedPostData) => {
    const updatedPost = await Posts.findByIdAndUpdate(
        id,
        updatedPostData,
        {
            returnDocument: 'after',
            runValidators: true
        }
    );

    return updatedPost;
}
```

### Important Options

`returnDocument: 'after'`

Returns the updated document instead of the original document.

`runValidators: true`

Ensures Mongoose schema validation is applied during the update.

The controller returns HTTP 404 when no document exists for the supplied ID.

## 10. Delete Operation

File:

```text
src/services/posts.services.js
```

Implementation:

```javascript
const deletePost = async (id) => {
    const deletedPost = await Posts.findByIdAndDelete(id);
    return deletedPost;
}
```

Before calling the service, the controller checks authorization.

```javascript
const currentId = req.user.id;

const post = await postService.getPostById(id);

if(post.author.toString() !== currentId){
    return res.status(403).json({
        success: false,
        error: {
            message: "You are not authorized to delete this post"
        }
    })
}
```

Only after this check does the controller call:

```javascript
await postService.deletePost(id);
```

The successful deletion returns:

```text
204 No Content
```

## 11. Validation

Post creation rules are defined in:

```text
src/routes/posts.routes.js
```

Create validation requires:

```javascript
body('title').notEmpty()
body('content').notEmpty()
```

Update validation allows the fields to be optional but prevents empty values:

```javascript
body('title').optional().notEmpty()
body('content').optional().notEmpty()
```

Validation errors return HTTP 400.

## 13. MongoDB Error Handling

File:

```text
src/index.js
```

The application handles Mongoose errors centrally.

### Invalid ObjectId

A Mongoose `CastError` is converted to HTTP 404.

### Duplicate Value

MongoDB duplicate-key error code `11000` is handled separately.

### Schema Validation Error

Mongoose `ValidationError` is converted to HTTP 400.

### Unexpected Error

Other errors return HTTP 500.

## 15. Schema Modeling Summary

The application uses Mongoose schemas to model two MongoDB collections:

```text
User
Post
```

The schemas define:

* Field types
* Required fields
* Unique constraints
* String transformations
* ObjectId relationships
* Automatic timestamps

The Post model references the User model through the `author` ObjectId.

This provides a structured data model while allowing related user information to be retrieved through Mongoose `populate()`.
